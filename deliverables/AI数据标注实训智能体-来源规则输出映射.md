# AI 数据标注实训智能体 · 来源—规则—输出映射审计

审计日期：2026-09-12  
审计范围：`a3-student-react-web/src/pages/AIAnnotationAgent.tsx`、竞赛说明、证据矩阵

## 1. 规则库与来源边界

页面内置 3 条核心执行规则，另有 60 条候选知识条目。核心规则的 ID、来源编号（S1/S2/S3）、来源定位和审阅状态与界面一致；知识条目额外覆盖任务理解、坐标、遮挡、截断、实例拆分、质检、导出与合规主题。用户输入先经过关键词意图识别：命中一条时匹配该核心规则，命中多条时先澄清而不擅自选择；右侧“知识依据”可展开完整知识目录。页面不宣称这些候选内容已经替代学校标注平台的 schema 或教师实训手册。

| 来源编号 | 来源 | 可以支持的内容 | 明确不能直接支持的内容 | 核验状态 |
|---|---|---|---|---|
| S1 | 哈工大大数据集团有限公司《数据标注职业技能等级标准（2021 年 1.0 版）》 | 图像 2D 拉框、标注任务质量/审核能力的职业等级要求 | 本校平台的 `occluded`/`truncated` 字段名、取值和阈值 | 候选来源，待教师按持有版本复核 |
| S2 | 人力资源和社会保障部、工业和信息化部《人工智能训练师国家职业技能标准（2021 年版）》；职业编码 4-04-05-05；人社厅发〔2021〕81 号 | 数据标注工种定位、准确性/完整性审核能力 | “同类实例必须分别标框”等平台操作细则 | 候选来源，待教师按持有版本复核 |
| S3 | Microsoft COCO Dataset Data Format | `bbox=[x,y,width,height]`、`area`、`iscrowd`、左上角 0-indexed 坐标结构 | `occluded`/`truncated` 字段及学校平台边界校验政策 | 官方格式参考 |
| S4 | 学校标注平台 schema、课程实训手册或教师核验记录 | 本校字段名、取值、必填性、边界和质量阈值 | 未取得核验前不得写成已知事实 | 待补真实材料 |

## 2. 规则到页面输出

| 规则 ID | 触发输入示例 | 页面输出 | 输出中的保守表述 | 对应竞赛要求 |
|---|---|---|---|---|
| `ANN-OCC-01` | “人被车挡住了，框怎么画” | 4 步框选流程、常见错误、`occluded` 提示、来源 | “常见字段名”“以学校平台 schema/教师核验版为准” | 2、3、4、7 |

每次命中结果还显示 `sourceId`、来源定位、`candidate/verified` 状态和实际命中的关键词；当前 3 条核心规则与 60 条知识条目均为 `candidate`，待教师复核后才可改为 `verified`。知识条目数量是目录覆盖量，不代表已核验条款数量。

## 3. 交互闭环证据

```text
文字输入
  ↓
关键词意图识别（遮挡 / 截断 / 同类实例；无法判断时追问）
  ↓
规则库匹配（单一候选命中 1 条；多意图先澄清）
  ↓
规则 ID/来源追踪 + 步骤 + 错误提示 + 属性字段提醒 + 依据
  ↓
用户阅读并提交试用反馈（记录类型、匿名身份、评分、意见、时间、匿名确认）
  ↓
localStorage 保存 → 按记录类型导出 CSV
```

自动化脚本 `npm run smoke:ai-annotation-agent` 已覆盖登录保护、BiliLearn 主线入口、主/兼容地址、工单生成学习任务卡、三类规则、规则追踪元数据、多意图澄清、模糊追问、反馈确认、反馈连续录入、记录类型和 CSV 导出。自动化结果只证明技术路径，不证明真实场景或真实用户测试。

## 4. 提交前必须补的核验

1. 由真实课程教师确认课程/平台名称、版本和字段 schema，并在 `AI数据标注实训智能体-场景来源核验模板.md` 留存脱敏记录。
2. 将团队实际持有的标准封面、相关条款页码/截图和教师复核记录放入补充材料；不上传无授权整本标准。
3. 由 2 名人工智能专业学生和 1 名计算机视觉/数据标注教师实际操作页面，选择“真实用户试用”后导出正式 CSV，并附经同意的书面反馈、访谈纪要或视频。
4. AI 模拟记录、开发者自测和 Playwright 截图只能作为内部演示/技术回归证据，不能替代上述三项外部核验。

**审计结论：**代码与候选来源的对应关系已明确，规则边界没有把 COCO 或两份标准夸大为学校平台细则；第 1、3、8 项仍需真实材料才能达到正式提交条件。
