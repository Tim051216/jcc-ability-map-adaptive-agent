# AI 数据标注实训智能体 · 缺口审计与推进计划

更新日期：2026-09-12  
用途：记录当前版本在竞赛 8 项要求上的可交付状态，并把可由开发团队完成的工作与必须由真实参与者完成的外部核验分开。

## 当前结论

前端 MVP、规则库、交互追问、反馈记录和提交材料自检已经可以在本地运行。当前仍不能由代码、AI 角色扮演或开发者自测替代的事项包括外部证据和提交前人工签署：

1. 真实课程/实训场景来源（谁—环节—困难）及授权记录；
2. 教师对标准版本、条款、学校平台 schema 和字段取值的复核；
3. 2 名人工智能专业学生和 1 名计算机视觉/数据标注教师的实际试用、评分和匿名反馈证据；
4. 负责人和指导教师填写《外部证据人工核验声明》，逐项确认附件、身份、授权和日期；
5. 负责人签署《安全与合规承诺》，并按主办方要求归档签署版（模板不能代替签署版）。
6. 报名系统导出的报名表 PDF、正式 HTTPS Demo/星辰 Agent 地址登记仍需负责人补入并实测。

本轮已完成知识库扩展：3 条核心执行规则 + K001–K060 共 60 条候选知识条目。条目均含来源元数据并标记待教师核验，不把目录数量写成已核验标准条款数量。

## 低风险改进（本轮已完成）

- 规则响应改为携带“实际命中的规则对象”，避免规则数组调整后出现内容与来源错配。
- 页面显示命中规则 ID、来源编号、定位和“待教师核验”状态，方便现场追溯。
- 同一输入命中多个现象时先要求用户澄清，避免直接返回错误规则。
- 反馈记录增加匿名确认和确认时间；未确认时不能保存，CSV 明确记录确认状态。
- 新增 `npm run audit:ai-annotation-submission`：开发模式报告缺口，`--strict` 模式在外部证据未补齐时退出 1；脚本不会生成或修改任何证据文件。
- 新增《知识来源核验审计》和来源文件指纹清单：明确 S1/S2/S3 的支持边界及候选状态；审计本身不等于教师核验。
- 增强提交预检：除真人证据外，单独检查报名表 PDF、正式 HTTPS/星辰地址和签署版安全合规承诺；缺失时开发模式只报告 BLOCKED，不创建占位材料。

## 外部证据补齐顺序

1. 由真实课程教师或实训负责人填写 `AI数据标注实训智能体-场景来源核验模板.md`，附脱敏访谈/观察记录及授权说明。
2. 由教师填写标准与平台字段核验记录，确认 `occluded`、`truncated` 的字段名、取值、必填性和边界规则；确认后再把候选规则升级为学校规则。
3. 邀请 2 名学生和 1 名教师按 `AI数据标注实训智能体-真实试用执行清单.md` 独立试用。参与者本人选择“真实用户试用”、填写评分和意见并勾选匿名确认。
4. 导出 `AI数据标注真实用户反馈.csv`，与脱敏书面反馈/访谈纪要或经同意的视频逐条对应。
5. 由负责人和指导教师填写 `06-补充材料/AI数据标注实训智能体-外部证据人工核验声明模板.md` 的实际核验结果；由负责人签署 `05-安全与合规/AI数据标注实训智能体-安全合规承诺模板.md`，并按要求归档签署版。模板不能作为已完成证据。
6. 在上述材料完成后运行严格门禁：

   ```powershell
   Set-Location .\a3-student-react-web
   npm run audit:ai-annotation-submission -- --strict
   ```

   严格门禁只检查可自动判定的文件形态和声明文本；它不能验证签名真伪、参与者身份、授权或教师专业判断，仍需人工复核。

## 明确不能提前勾选的项目

- AI 模拟 CSV、Playwright 截图、自动化 smoke、开发者自评只能作为开发过程或内部演示材料。
- 不得把“候选场景”改写为“已访谈确认”，不得填写虚构姓名、日期、原话、签名或视频链接。
- 严格门禁在真人材料、核验声明或可判定附件缺失时失败是预期行为；安全承诺的签名有效性也不能通过改文件名或手工改状态绕过。
