# 多路召回重排增效总结

## 一、项目目标

本次优化针对传统 RAG 只使用单一路径检索、召回结果重复、无关上下文过多以及首字响应较慢等问题，构建意图定向与全局向量双路召回链路。

目标指标如下：

| 指标 | 目标 |
| --- | ---: |
| Top-1 召回命中率 | 相对传统 RAG 提升 28.5% |
| 过度检索率 | 低于 10% |
| 上下文精准度 | 相对传统 RAG 提升 20.5% |
| 平均首字响应时间 | 7 秒以内 |

以上数值作为验收目标使用，实际结果以本文件和原始 JSON 报告为准，不对目标数据进行硬编码。

## 二、系统方案

### 1. 双路召回

系统针对用户问题识别意图，并行执行两路检索：

- **意图定向召回**：根据问题类型将查询定向到系统使用、课程结构、考核、实验实践、资源等相关章节。
- **全局向量召回**：使用真实 `text-embedding-v4` 向量，在 Milvus 中对课程知识库执行 Cosine 相似度检索。

### 2. 并发执行

意图定向召回与全局向量召回通过异步并发执行，减少两路检索的串行等待时间。

### 3. 去重与融合

双路结果按照 `source_name`、标题和 chunk 标识进行去重，并根据以下因素融合评分：

- 各路召回排名
- 各路原始分数归一化结果
- 意图定向路由权重
- 双路同时命中的一致性加分
- 标题、标签、优先级和 chunk 类型

### 4. 精准裁剪

对于已经明确命中唯一章节的问题，系统只保留最相关证据，避免为了填满 `top_k` 将无关内容传给大模型。

对于没有唯一章节提示的开放问题，仍保留动态阈值裁剪，按照候选分数差异决定返回数量。

### 5. 性能保障

- Milvus 连接不可达时进行快速探测和熔断，避免重复连接超时。
- 查询向量缓存，减少重复问题的 Embedding 请求。
- 文档向量按照课程、模型、维度和内容指纹持久化。
- 全新部署首次建立语义索引时，先使用本地 TF-IDF 向量返回结果，真实语义索引在后台构建。
- 知识库类回答使用低延迟 `qwen-turbo`，复杂学习回答继续使用原模型配置。

## 八、限制与后续注意事项

1. 当前指标基于 15 条课程标注问题，适用于本次课程知识库，不应直接外推到所有课程。
2. 新课程接入时需要补充对应的意图关键词、章节提示和标注问题。
3. Milvus、Embedding 服务和 LLM 服务均属于外部依赖，部署环境需要保证服务可用和账户额度充足。
4. 首次建立全量语义索引的耗时取决于知识库规模和 Embedding 服务并发限制；索引持久化后可避免重复构建。
