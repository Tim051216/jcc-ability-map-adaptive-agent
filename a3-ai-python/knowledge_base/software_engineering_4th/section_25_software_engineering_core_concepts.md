# 软件工程核心概念速查

## 可行性分析

可行性分析用于在项目立项和开发计划形成前判断软件项目是否值得实施。常见评估维度包括技术可行性、经济可行性、操作可行性和法律可行性。技术可行性关注现有技术、团队能力、软硬件环境是否支持实现；经济可行性关注成本、收益、预算和投资回报；操作可行性关注用户、组织流程和运行环境是否能够接受系统；法律可行性关注版权、数据合规、安全责任和合同约束。

## 概要设计

概要设计位于需求分析之后，主要把需求模型转换为系统总体方案。该阶段通常完成系统总体结构设计、模块划分、模块之间的接口关系、数据组织方案和主要技术路线选择。概要设计的输出强调“系统由哪些部分组成、各部分如何协作”，为后续详细设计提供结构依据。

## 详细设计

详细设计在概要设计基础上继续细化每个模块的内部实现。该阶段的输出一般包括模块内部算法、数据结构、处理流程、输入输出约束、异常处理和必要的伪代码或流程图。详细设计强调“每个模块具体怎样实现”，使开发人员可以据此编码。

## 软件测试

软件测试的目标是通过执行程序发现缺陷、验证软件是否满足需求，并评估软件质量。测试不是为了证明软件完全没有错误，而是尽可能暴露问题、降低交付风险，并为质量改进提供依据。常见测试活动包括单元测试、集成测试、系统测试和验收测试。

## 软件维护

软件维护是在软件交付和运行后对系统进行修改和完善的活动。适应性维护是为了适应新的操作系统、硬件环境、外部接口、业务规则或运行环境变化而进行的软件修改。它不同于纠错性维护，重点不是修复已有缺陷，而是让软件继续适配变化后的外部条件。
