# BiliLearn 本地启动与联调说明

## 本地常用端口

项目本地开发时常见端口如下：

- `3002`：学生端前端
- `3004`：管理端前端
- `18080`：Python AI 中台
- `10010`：Java 网关
- `8090`：学习与测评相关 Java 服务
- `8085`：消息或通知相关服务
- `15432`：本地 PostgreSQL
- `16379`：本地 Redis
- `19000`：MinIO
- `19001`：MinIO Console

## 学生端怎么启动

进入 `a3-student-react-web` 后：

1. 执行 `npm install`
2. 执行 `npm run dev`
3. 默认访问 `http://localhost:3002`

项目已经建议只保留一个学生端实例。正常情况下只应该使用 `3002`，不应该同时存在 `3002` 和 `3003` 两个学生端端口。

## 为什么有时会出现 3003

如果用户重复启动了学生端，而 `3002` 已经被占用，Vite 可能自动顺延到 `3003`。这会导致：

- 两个窗口看起来像同一个项目，但其实是两个独立开发实例
- 页面状态、缓存、登录态和代理链路可能不一致
- 容易误判“我改了代码但页面没同步”

当前更合理的做法是：

- 只保留 `3002`
- 配置 `strictPort: true`
- 端口被占用时直接报错，不自动漂移到 `3003`

## Python AI 中台怎么启动

推荐从仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-ai-local.ps1
```

如果手动启动，也应优先使用项目自己的虚拟环境：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 18080
```

## 启动 AI 中台前要确认什么

至少需要确认这些依赖可用：

- PostgreSQL
- Redis
- MinIO
- Milvus（如果要做向量检索）
- 对应 `.env` 已配置

健康检查地址：

- `http://127.0.0.1:18080/health`

## Java 网关和业务服务的作用

如果学生端走 `/ai/**` 代理链路，通常还会经过 Java 网关。即使 AI 服务本身可用，如果网关或消息服务未启动，部分学生端能力仍可能异常。

常见联调关系：

- 学生端通过 `3002` 访问
- 学生端 `/ai` 请求代理到 `18080`
- 或者 Java 网关统一转发到 Python AI 中台

## 联调时推荐的检查顺序

如果页面提示“不可用”“白屏”“接口失败”，建议按这个顺序检查：

1. 学生端 `3002` 是否正常打开
2. `18080/health` 是否返回 `200`
3. 如果走网关，再检查 `10010` 是否正常
4. 再检查具体接口，例如 `/api/v1/chat`、`/api/v1/rag/search`

## 常见误区

### 误区 1：两个前端端口会自动同步

不会。`3002` 和 `3003` 如果同时存在，通常是两份独立 Vite 实例。

### 误区 2：AI 服务启动了就一定能问答

不一定。AI 服务启动只是前提，还要看：

- 依赖组件是否可用
- 知识库是否已入库
- 模型配置是否有效

### 误区 3：所有能力都必须依赖真实大模型

不是。很多页面可以先依赖本地知识库、预置资源和稳定业务链路，再逐步接入真实模型。
