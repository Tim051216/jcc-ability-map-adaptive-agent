# AI 数据标注实训智能体项目说明

报名信息：作品编码 600370；学校为南京林业大学；负责人韩盛豪；成员张文馨、蒋孟窈、朱佳音；指导教师徐雨凤、张晓丹。盖章报名表登记的作品名称为“面向软件工程专业群的岗课赛能力图谱构建与全闭环自适应导学智能体”，本说明展示其当前完成度最高的 AI 数据标注实训智能体实施模块。两者专业群口径不一致，正式提交前须由负责人在赛事中心确认，本文档不篡改盖章报名信息。

## 1 项目摘要

本作品面向人工智能技术应用专业群的计算机视觉教学实训，服务 AI 数据标注工程师岗位，明确覆盖赛题核心方向 3“岗位典型工作任务转化成学习型任务”。学生输入真实或脱敏后的目标检测标注工单，智能体从 3 条核心执行规则中匹配一条候选规则，自动生成包含任务名称、工作情境、操作步骤、知识点、技能点、安全要点、提交产出、量化验收和来源的学习任务卡；随后还可继续询问遮挡、截断或同类实例粘连的框选与质检问题。60 条候选知识条目补充任务理解、坐标、质检和合规提示，页面右侧用明确标注为“示意图（非真实样本）”的图示帮助理解边界。

当前技术 MVP 已可运行。场景来源、学校平台字段和真人试用仍需团队按模板补齐，材料中不把候选内容或 AI 模拟记录写成外部事实。

## 2 场景与痛点

候选场景描述为：人工智能专业学生在目标检测标注实训的框选与提交质检环节，对遮挡、截断和同类目标边界判定不一致，容易出现漏标、误合并或质检返工。

正式提交须附真实课程/实训观察或教师访谈记录，至少写清楚身份、环节、可观察困难、影响和样本范围，模板见 `AI数据标注实训智能体-场景来源核验模板.md`。

## 3 微任务闭环

```text
接收真实/脱敏工单 → 关键词意图识别 → 匹配 1 条核心执行规则
→ 生成完整学习任务卡 → 对话追问框选与质检 → 反馈保存与 CSV 导出
```

规则库位于 `a3-student-react-web/src/data/aiAnnotationRules.ts`，含 `ANN-OCC-01`、`ANN-TRU-01`、`ANN-INS-01` 三条核心规则和 K001–K060 共 60 条候选知识条目。未能判断意图时，页面先要求用户补充任务类型和现象，支持连续追问。

## 4 功能实现

| 功能 | 实现方式 | 输出证据 |
|---|---|---|
| 文字输入 | React 输入框、快捷问题和回车发送 | 对话消息记录 |
| 工单转学习任务 | 规则工作流生成情境、步骤、知识/技能、安全、产出和量化验收 | 完整学习任务卡 |
| 规则调用 | 关键词意图识别并匹配 1 条规则 | 规则 ID、来源和状态 |
| 逻辑处理 | 遮挡/截断/实例粘连分支与模糊澄清 | 分支化回答 |
| 结果生成 | 步骤列表、警示提示、属性和质检项 | 页面结果区 |
| 反馈闭环 | 本地保存、连续记录 A/B/C、按类型导出 CSV | 反馈 CSV |

## 5 专业内容与来源

| 来源 | 使用范围 | 限定 |
|---|---|---|
| 《数据标注职业技能等级标准（2021 年 1.0 版）》 | 图像 2D 拉框和质量审核能力范围 | 属于职业技能等级标准，不等同于国家职业标准 |
| 《人工智能训练师国家职业技能标准（2021 年版）》 | 数据标注工种定位与准确性/完整性审核能力 | 不直接给出学校平台字段操作细则 |
| Microsoft COCO Dataset Data Format | `bbox`、`area`、`iscrowd` 结构参考 | 不定义 `occluded`、`truncated` |
| 学校平台 schema 和教师核验版手册 | 本校字段名、取值、阈值 | 当前待真实补证 |

页面将候选来源显示在每条规则下方，并明确“待教师核验”。来源文件指纹见 `AI数据标注实训智能体-来源文件核验清单.md`。

## 6 交互设计

页面采用口语化提示和编号步骤。输入“这个怎么弄？”时，智能体不会直接编造结论，而是询问遮挡、截断、同类实例以及目标检测/实例分割任务类型。回答中的 `occluded` 和 `truncated` 使用“常见字段名 / 以学校平台 schema 为准”的保守表述。

## 7 技术实现

- 前端：React 19、TypeScript、Vite、Tailwind CSS、Lucide 图标。
- 页面入口：`/annotation-agent`，兼容 `/ai-annotation-agent`。
- 规则层：独立 TypeScript 规则模块，页面负责检索、解释和呈现。
- 反馈存储：浏览器 `localStorage`，按记录类型生成 CSV；不上传真实图片或个人敏感信息。
- 页面顶部、场景提示和每条助手回答显示“AI生成内容 · 教学辅助”，并明确提交前需教师核验；该标识不代表真人反馈或已确认的学校平台规则。
- 启动：`scripts/start-ai-annotation.ps1`，默认端口 3002。

## 9 验收命令

```powershell
Set-Location .\a3-student-react-web
npm run lint
npm run build
npm run smoke:ai-annotation-agent
npm run audit:ai-annotation-deliverables
```

自动化验收只能证明代码和技术路径，不替代真实场景来源、教师复核或真人反馈。最新回归结果以 `AI数据标注实训智能体-自动化验收记录.md` 为准；隔离解压副本的安装、构建和 smoke 复现结果以对应预提交包验真记录为准。

## 10 提交限制与后续动作

提交前须补齐真实场景核验、教师标准/平台 schema 复核、2 名学生和 1 名教师试用证据，并确认团队具有标准文件的使用授权。AI 模拟试用记录仅作为内部演示材料，不能改名为真实反馈。

## 11 适配方法与范围

规则层与知识目录层分离，适配新岗位时只需替换条目内容、触发词、来源定位和平台字段校验，并为新意图补充核心规则与 smoke 用例；输入、追问、步骤反馈、匿名记录和 CSV 导出接口保持不变。当前可迁移到计算机视觉框选/分割、语音切分、文本分类等数据标注教学任务；生产质量判定和安全关键决策仍须教师或企业专家复核。
