# BiliLearn 常见问题与排障说明

## 为什么会出现两个学生端端口

如果同时看到 `3002` 和 `3003`，通常说明学生端前端被启动了两次。

常见原因：

- 第一次启动占用了 `3002`
- 第二次再次执行 `npm run dev`
- Vite 发现 `3002` 被占用，于是自动改用 `3003`

更稳的做法是：

- 只保留一个学生端实例
- 锁定 `3002`
- 配置 `strictPort: true`

## 两个端口会自动同步吗

不会。即使它们读的是同一份代码目录，也仍然是两个独立开发实例。

可能不一致的包括：

- 当前页面状态
- 会话缓存
- 登录态
- 本地存储
- 代理链路行为

## 为什么 IM 一开始看起来像是假聊天

因为很多项目初版会先用本地 demo 数据占位。判断一个聊天页是不是真接通，要看三件事：

1. 会话列表是不是来自真实接口
2. 消息列表是不是来自真实接口
3. 发送消息后再次拉列表能不能读到刚发的消息

如果这三项只有 UI 有、接口没接通，那就是假聊天或半真半假聊天。

## 注册用户能不能聊天

判断标准不是“页面上能输入”，而是：

- 是否存在真实会话
- 是否能创建会话
- 是否能发送消息
- 是否能再次查询到最新消息

只有这四步都成立，才能说“注册用户可以真实聊天”。

## 为什么会出现白屏

白屏常见原因包括：

- 前端页面渲染时报错
- 数据结构和页面预期不匹配
- 开发实例开了两份导致状态混乱
- 后端接口 500，前端没兜底
- 某个路由懒加载页面本身存在运行时错误

排查顺序建议：

1. 看浏览器控制台
2. 看开发终端
3. 确认当前只保留一个前端实例
4. 确认接口是否返回 200

## 为什么会出现乱码

项目里出现乱码通常有三类原因：

1. 历史文件本身编码被污染
2. 某些中文文案经过错误编码转换
3. 终端、日志或旧数据在不同环境下被错误解码

如果是知识库文档，建议统一使用 UTF-8 保存，并尽量新增干净文件，而不是在严重乱码文件上继续叠加修改。

## AI 服务可用但页面还是报错怎么办

这说明“服务启动”不等于“链路完全打通”。要继续检查：

- 代理是否指向正确后端
- 网关是否正常
- 当前接口是否真的存在
- 参数、鉴权和用户信息是否正确

## 管理端触发知识入库后，AI 导师还是答不出来怎么办

可能原因有：

- 文档没有真正写入对应课程知识库目录
- 入库接口没有成功执行
- 向量存储或检索链路未正常工作
- 问题本身更像系统使用问题，而不是课程概念问题

这时可以优先确认：

1. 文档是否在 `knowledge_base/{course_code}` 下
2. 入库接口是否成功
3. `rag/search` 是否能检索到相关片段

## AI 导师回答项目问题时的优先策略

如果用户问的是“这个系统怎么用”，优先使用项目使用文档知识库。

如果用户问的是“某个课程知识点是什么”，优先使用课程知识库。

如果两者都有关系，例如“这个页面上下一步该做什么”，可以先解释页面用途，再结合课程上下文给建议。
